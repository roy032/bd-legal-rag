# Coverage beyond the Acts, and the "what we can't answer yet" page (2026-10-28)

## What changed

The index held only the Acts and Ordinances on bdlaws. Three kinds of law people need
were missing: rules and regulations made under an act (fees, forms, deadlines), SROs and
gazette notifications, and court judgments. This change adds the machinery for all of
them and a first batch of judgments, and a public page that says what is and is not
covered.

| Piece | Where |
|---|---|
| Source manifest, official hosts only | `data/sources/manifest.jsonl`, `src/ingest/sources.py` |
| `bdrag sources check / list / discover / fetch / ingest` | `src/bdrag_tools/sources.py` |
| Judgment chunker (overview + page-anchored body) | `src/ingest/judgment.py` |
| Rules and SROs, cited as "বিধি 5" / "rule 5" | `doc_type` on `Act` and every chunk (`src/ingest/chunk.py`) |
| `/coverage` page and JSON | `src/service/coverage.py` |
| Known gaps, both languages, hand-written | `data/coverage/known_gaps.json` |
| Publishable unanswered questions | `bdrag gaps --public data/coverage/public_gaps.json` |

## Measured in the cloud (no laptop)

- `bdrag sources discover --division HCD AD --limit 8` read the Supreme Court's latest
  lists: 16 judgments, all on supremecourt.gov.bd.
- `bdrag sources fetch`: 16 of 16 downloaded (one needed a second try).
- `bdrag sources ingest --ocr never` on the first 15: 280 chunks; every one has a text
  layer, so no OCR was needed. Case numbers were read correctly for all 15 ("First Appeal
  No. 311 of 2016", "Civil Appeal No. 73 of 2023"); the decision date for 9 of 15. The
  Appellate Division PDFs print the date at the end in words, which is not parsed yet;
  put `"date"` in the manifest when it matters.
- With the sample index plus those chunks (hashing embedder, hybrid), "Artha Rin Adalat
  writ petition" ranks Writ Petition No. 8897 of 2026 first, and "city survey khatian
  presumption of correctness" ranks First Appeal No. 639 of 2019, p. 6 first.
- Tests: 472 pass, ruff clean.

Not measured: whether judgment chunks push statute sections out of the top 5 on the
full 43,966-chunk index. 296 judgment chunks against 44k statute chunks should not
matter much, but the eval below says for sure.

## Laptop: re-index with the new sources

In `C:\Users\Roy\Desktop\bd-legal-rag`, PowerShell, with the venv active:

```powershell
git fetch origin
git checkout claude/project-thread-nih3a7
git pull
pip install -e ".[pdf]"

# 1. Baseline before the change (the current index)
bdrag eval --label before-sources

# 2. Download and chunk the judgments in the manifest (about 16 MB, 2 s between files)
bdrag sources check
bdrag sources fetch
bdrag sources ingest
bdrag sources list

# 3. Rebuild. No --chunks: the default now reads chunks.jsonl, pdf_chunks.jsonl and
#    source_chunks.jsonl, and only the ~300 new chunks are embedded (stored vectors
#    are reused). Keep any flags you built the current index with (e.g. --bm25-stem).
bdrag index --bm25

# 4. Same eval after; compare. Recall@5 should not drop.
bdrag eval --label after-sources
bdrag compare results/before-sources.json results/after-sources.json --baseline before-sources

# 5. Optional: more judgments (50 per division is the whole first page of each list)
bdrag sources discover --division HCD AD --limit 50
bdrag sources fetch
bdrag sources ingest
bdrag index --bm25
```

If step 4 shows a drop, open an issue in this thread with the compare output before
deploying; the fix is to down-weight `doc_type=judgment` in fusion, not to remove them.

Then restart the service and open `http://localhost:8000/coverage`.

## Publishing the unanswered questions

After the service has been live a while:

```powershell
bdrag gaps --public data/coverage/public_gaps.json
notepad data/coverage/public_gaps.json     # read every line before deploying
```

Only questions that at least 3 different visitors asked are written (`--min-visitors`,
never below 2), redacted again for phone, NID, card numbers and emails, clipped to 200
characters, with no comments or dates. The file is git-ignored on purpose. Delete any
line that still names a person or place that could identify someone. The privacy page
now tells visitors this list exists; read that paragraph before launch, with the rest of
the privacy text.

## Adding rules and SROs

None are in the manifest yet: the Bangladesh Gazette site (dpp.gov.bd) did not answer
from the cloud, and a rule's official PDF has to be found by hand. On the laptop, find
the gazette PDF for a rule that the topic table's common questions need (consumer rights
rules, the labour rules 2015, the land development tax rules), add one line each to
`data/sources/manifest.jsonl` as in `data/sources/README.md`, and run steps 2 to 4.
Rules are split at "১।", "২।" like an act and cited as "বিধি ২".

## Not done here

- The answer prompt still calls every excerpt "the current consolidated text". The
  excerpt header now says `[COURT JUDGMENT, date]` or `[RULE under …]`; a prompt rule on
  how to use a judgment (say "the High Court held", never present it as the statute)
  should be a new prompt version, measured with `bdrag e2e`, not slipped in here.
- No reported cases (DLR, BLD, BLC): those are paid law reports.
- Appellate Division decision dates written in words at the end of the PDF.
